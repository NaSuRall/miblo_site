Relations

Une clé étrangère relie un champ au id d’un autre modèle.

▶ Voir l’ajout d’une relation →

User.group_id → Group.id

  1. Créez Group avec un champ name.
  2. Ajoutez User avec a. Après ses champs, choisissez Ajouter une relation (clé étrangère).
  3. Sélectionnez Group → groups.id et validez le nom proposé group_id.
  4. Choisissez les options, puis la règle de suppression.
  5. Terminez et confirmez la génération.

Miblo génère un entier, un index et une contrainte SQL. Pour User déjà créé, passez par m → Ajouter une relation facultative.

En ligne de commande
shell
miblo add Group name:string --yes
miblo add User name:string 'group_id:int?:ref=Group' --yes

Choisir la règle de suppression

RègleEffet sur les lignes liées
RESTRICT (défaut)Bloque la suppression de la cible tant qu’elle est référencée.
CASCADESupprime également les lignes qui la référencent.
SET NULLConserve les lignes et remplace la référence par NULL ; nécessite un champ facultatif.
shell
miblo add Note body:text 'user_id:int?:ref=User:on_delete=set_null' --yes

Relations uniques et autoréférences

:unique limite chaque valeur de référence non NULL à une seule ligne. Les autoréférences sont possibles :

shell
miblo add Folder name:string 'parent_id:int?:ref=Folder:on_delete=set_null' --yes

Le CRUD expose les identifiants, sans jointures ni objets imbriqués automatiques. Les clés primaires personnalisées/composites et les tables plusieurs-à-plusieurs automatiques ne sont pas générées.

Lire le schéma

  1. Appuyez sur d pour ouvrir le schéma réel.
  2. Sélectionnez une table : colonnes, clé primaire, clés étrangères et règles de suppression s’affichent à droite.
  3. p bascule vers les modèles déclarés. F5 actualise, d revient aux routes.

Les tables créées à la main sont aussi visibles. Les tables internes SQLite et SQLx sont masquées. Cette vue affiche la structure ; testez les routes pour consulter les lignes.

En ligne de commande
shell
miblo db schema --project team-api
