Référence du CLI

Les commandes utilisables dans le shell et dans vos scripts.

Aide et commandes principales

shell
miblo --help
miblo --version
miblo new --help
miblo route add --help
CommandeUsage
mibloOuvre le TUI dans un terminal interactif.
miblo ui --project PATHOuvre un projet.
miblo new [NAME]Crée une API.
miblo add [NAME] [FIELD]...Ajoute un modèle.
miblo edit NAME [FIELD]...Ajoute des champs facultatifs.
miblo route add NAME --path PATHCrée une route.
miblo run --project PATHExécute cargo run.
miblo doctor --project PATHContrôle métadonnées, registres et prérequis.
miblo db ACTION --project PATHcheck, init, migrate ou schema.
miblo template updateActualise le template des futurs ajouts.

Créer : miblo new

shell
miblo new shop-api --database sqlite --port 3000 \
  --resource Product --field title:string --field price:float --yes
OptionRôle
--output PATHDestination ; un dossier existant est refusé.
--database sqlite|mysqlSQLite par défaut en interactif ; MySQL pour --yes sans moteur explicite.
--port PORT3000 par défaut.
--resource NAME / --field FIELDModèle initial et champs répétés.
--config PATHDéfinition YAML version 1.
--template-dir PATHPack local ; incompatible avec URL/digest directs.
--template-url URLArchive directe.
--template-base-url URLServeur de distribution.
--template-version VERSIONVersion du pack.
--sha256 HEXDigest sans téléchargement du sidecar.
--yes / --dry-runAccepter les choix / voir le plan sans écrire le projet.
--offline / --cache-dir PATHCache des templates.

Ajouter et faire évoluer

shell
miblo add User name:string email:string:unique --yes
miblo edit User 'nickname:string?' --yes

Les champs sont positionnels ou fournis avec --field répété, jamais les deux à la fois. L’ancien miblo add resource User --field name:string --yes reste accepté.

Options communes : --project, --yes, --dry-run, --offline, --cache-dir. add accepte aussi --path. edit exige des champs facultatifs et un modèle existant.

Créer une route

shell
miblo route add create_member --resource User --action create --path /members --yes
miblo route add activate --method POST --path '/users/{id}/activate' --resource User --json-body --yes

--action list|get|create|update|delete exige --resource et déduit la méthode. Sans action, --method et --json-body décrivent le squelette. Autres options : --project, --yes, --dry-run, --offline, --cache-dir.

Changer les templates

shell
miblo template update --project team-api --dry-run
miblo template update --project team-api

Options : --template-dir ou --template-url, --template-version, --template-base-url, --project, --dry-run, --offline et --cache-dir. Consultez --help sur votre version avant d’automatiser un nouveau scénario.
