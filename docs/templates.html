Templates & mode hors ligne

Les templates sont téléchargés, vérifiés et mis en cache. Ils restent hors du binaire.

▶ Voir la création avec les templates →

Les packs disponibles

Les nouveaux projets utilisent le format 3 et les packs 0.6.0. Le CLI comprend aussi les formats 1 et 2.

BasePack
SQLiterust-axum-sqlite.tar.gz
MySQLrust-axum-mysql.tar.gz

Chaque archive possède un sidecar .sha256. Le projet épingle version, URL, digest et empreinte. Les templates ne sont pas intégrés au binaire.

Utiliser le cache

shell
miblo add Note body:text --yes --offline

Le mode offline exige un template déjà téléchargé. --cache-dir ou MIBLO_CACHE_DIR choisit le dossier ; sinon XDG_CACHE_HOME, LOCALAPPDATA ou ~/.cache/miblo sont utilisés.

Le cache de templates est distinct du cache Cargo. Compiler hors ligne exige aussi les dépendances Rust.

Changer de version

Appuyez sur u, choisissez GitHub Releases, un dossier local ou une URL. Confirmez avec Mettre à jour.

En ligne de commande
shell
miblo template update --project team-api

Le nouveau pack sert aux futurs modèles et routes. Les modèles existants conservent leur pack ; leurs sources et migrations restent inchangées.

Héberger ou développer un pack

shell
miblo new team-api --database sqlite \
  --template-base-url https://templates.example.com --yes

miblo new team-api --database sqlite \
  --template-url https://templates.example.com/custom/api.tar.gz \
  --template-version 0.6.0 --yes

Remplacez ces URL d’exemple par votre serveur. Une URL de base est suivie de /v0.6.0/<stack>.tar.gz. --sha256 HEX fournit un digest connu. HTTPS est requis hors loopback de test.

shell
miblo new team-api --database sqlite \
  --template-dir ../miblo_templates/rust_sqlite_template_v4 --yes

Un pack local contient manifest.json et les fichiers Handlebars. Il doit rester disponible et inchangé. Les releases évitent de maintenir ce dossier local.

Contrôles du téléchargement

Miblo vérifie le SHA-256 et refuse les archives corrompues, les liens, les fichiers inattendus ou les chemins qui sortent du dossier. Une nouvelle version doit avoir une nouvelle archive.

Le SHA-256 vérifie le contenu téléchargé ; il ne remplace pas une signature de l’éditeur.
