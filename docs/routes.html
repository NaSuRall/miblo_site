Créer POST /members pour User

  1. Appuyez sur g et sélectionnez User.
  2. Choisissez Créer une ligne. La méthode POST est déduite.
  3. Saisissez /members, puis validez ou modifiez le nom de fonction proposé.
  4. Confirmez avec Créer les fichiers.
  5. Redémarrez l’API avec s, puis r, pour charger la route.

Cette URL utilise le CRUD et les requêtes SQL de User. Elle écrit dans users ; elle ne crée pas de nouvelle table.

En ligne de commande
shell
miblo route add create_member --resource User --action create --path /members --yes

Actions disponibles

Action CLIMéthodeChemin exemple
listGET/members
getGET/members/{id}
createPOST/members
updatePATCH/members/{id}
deleteDELETE/members/{id}

Les actions sur une ligne exigent un seul paramètre {id}. Lister et créer n’en acceptent pas. Plusieurs méthodes peuvent partager un chemin, avec des noms de modules distincts.

shell
miblo route add members --resource User --action list --path /members --yes
miblo route add member --resource User --action get --path '/members/{id}' --yes
[i]
Le chemin ne définit pas le métier

Une action list sur /users/active reste une liste paginée. Le nom de l’URL ne programme pas un filtre ou une permission.

Créer une fonction à compléter

Dans g, choisissez Logique personnalisée — sans modèle, ou un modèle puis Logique personnalisée — à compléter (501). Choisissez ensuite méthode, chemin, nom et corps éventuel.

En ligne de commande
shell
miblo route add activate_user --method POST --path '/users/{id}/activate' --resource User --json-body --yes

Les fichiers handlers.rs, requests.rs et service.rs sont créés dans src/resources/custom_routes/activate_user/. La réponse reste 501 jusqu’à l’implémentation de la fonction métier.

Sélectionnez la route puis e pour ouvrir son code. La fonction reçoit le pool SQL, les paramètres de chemin, les paramètres de requête et le JSON éventuel. Adaptez leurs types, complétez le traitement, puis redémarrez.

Templates, chemins et conflits

Les actions de modèle nécessitent le pack 0.6.0. Sur un ancien projet : u → GitHub Releases, ou miblo template update. Les anciens modèles conservent leur architecture.

Chemins : /segments/{parametres}, sans query string ni wildcard. Doublons méthode/chemin, collisions connues avec le CRUD ou /health sont refusés. GET réserve HEAD. Vérifiez vous-même les routes branchées hors de Miblo.

--dry-run montre le plan ; --offline réutilise le cache.
