Modèles et champs

Un modèle génère une table SQL, des fichiers Rust et cinq routes CRUD.

▶ Voir la démo →

Créer un modèle

  1. Appuyez sur a et nommez le modèle, par exemple User.
  2. Nommez un champ, choisissez son type, puis ses options avec Espace.
  3. Ajoutez d’autres champs ou une relation depuis Champs de la ressource.
  4. Choisissez Terminer et générer, validez le chemin de collection, puis Générer.

id est ajouté automatiquement. Utilisez des noms de champs comme first_name. Échap annule avant génération.

En ligne de commande
shell
miblo add User name:string email:string:unique --yes
miblo add Product title:string price:float active:bool --yes

--path /members change le chemin de collection. Sans champs ni --yes, le CLI ouvre son assistant.

Types de champs

TypeRustSQLiteMySQL
stringStringTEXTVARCHAR(255)
textStringTEXTTEXT
inti64INTEGERBIGINT
floatf64REALDOUBLE
boolboolINTEGERBOOLEAN

Un champ facultatif utilise Option<T>. Syntaxe : nom:type?:option, par exemple description:text?.

Options et champs privés

OptionExempleComportement
Facultatifnickname:string?Accepte NULL.
Uniqueemail:string:uniqueContrainte d’unicité. Utiliser string plutôt que text pour un texte unique.
Privétoken:string:privateÉcriture acceptée ; valeur omise des réponses CRUD.

Les noms sensibles courants (password, password_hash, secret, token, api_key) deviennent privés via le CLI. Ce filtrage ne chiffre pas les données et ne crée pas d’authentification.

Le CRUD produit

MéthodeChemin UserRésultat
GET/usersListe paginée : limit et offset, maximum 100 par page.
POST/usersCréation : 201.
GET/users/{id}Ligne ou 404.
PATCH/users/{id}Modification des champs fournis ; champs omis inchangés.
DELETE/users/{id}Suppression : 204 ; ligne absente : 404.

Champs inconnus et types incorrects sont refusés. Unicité : 409. Un PATCH vide, la modification de id et NULL sur un champ obligatoire sont refusés.

Préserver le projet existant

Un ajout crée les fichiers du nouveau modèle et sa migration sans régénérer les ressources existantes. Les registres, miblo.yaml et .miblo/state.json sont actualisés.

--dry-run montre le plan. Une collision de fichiers ou un conflit dans les registres gérés interrompt l’opération. Pour ajouter un champ, utilisez miblo edit ou m.
