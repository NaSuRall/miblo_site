Modifier un modèle

Ajouter des champs ou des relations à une table existante.

▶ Voir la démo →

Ajouter un champ

  1. Arrêtez l’API avec s, puis appuyez sur m.
  2. Choisissez le modèle et Ajouter un champ facultatif.
  3. Saisissez nickname, choisissez Texte court, puis validez les options.
  4. Choisissez Terminer et générer, relisez le SQL et confirmez.

Une nouvelle migration ALTER TABLE et les modifications Rust sont générées. Les anciennes lignes recevront NULL dans ce champ après application.

En ligne de commande
shell
miblo edit User 'nickname:string?' --dry-run
miblo edit User 'nickname:string?' --yes

Pour une relation, choisissez Ajouter une relation facultative et le modèle cible. Les règles de suppression s’appliquent aussi.

Appliquer la migration

  1. L’état BDD passe à Mise à jour BDD requise.
  2. Appuyez sur b → Appliquer les migrations, puis confirmez.
  3. Attendez Migrations à jour et relancez avec r.

Une modification de modèle n’applique pas sa migration automatiquement, y compris sur SQLite. Le lancement de l’API peut aussi appliquer les migrations en attente.

En ligne de commande
shell
miblo db migrate
miblo run

Conservez les migrations déjà appliquées sans les modifier.

Vos modifications de code

Miblo fusionne le code généré avec vos changements. Un conflit interrompt l’opération avant l’écriture. Les handlers et services des modèles actuels restent inchangés lors de l’ajout d’un champ.

Les fichiers remplacés sont copiés dans .miblo/backups/. Ces copies concernent les sources et métadonnées ; elles ne sauvegardent pas la base.

Modifications disponibles

Ajouter un champ facultatif, éventuellement unique.Renommer, supprimer ou changer le type d’une colonne.

Les ajouts conservent les lignes existantes. Miblo ne choisit pas de valeur de remplacement pour elles.
